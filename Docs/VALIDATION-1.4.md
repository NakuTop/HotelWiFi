# 1.4.0（build 17）验收记录

日期：2026-10-23

## 已完成

- Apple 的技术支持说明系统 LaunchDaemon 无法获得 Location 权限，应把 WiFi 身份读取移到由主应用管理的用户会话 Agent。本版采用 SMAppService.agent、AssociatedBundleIdentifiers 和签名固定的同用户 XPC。
- 本机服务响应：`identityReadable: true`，已安装应用显示“自动 AP 优化已就绪”。不修改 TCC 数据库，不解除系统保护。
- 自动 AP 流程已接入一键操作：比较同网络／同安全类型候选，优势至少 12 分且 RSSI 至少 -70 dBm，经两次扫描确认；加密保存恢复材料；请求关联；确认目标 BSSID；两轮正常网络请求；最终验证后提交。
- 无线 Agent 只能向特权服务请求有时效、次数限制、物理接口与配置核对的关联断开；无权修改 DNS 等配置。其他普通客户端不能调用该特权原语。
- 失败／停止／进程失联／超时会核对恢复，外部切网、配置变化及手动关闭 WiFi 会保留用户选择。
- 安装器已从已安装的 1.2 升级到 1.4，保留原应用；核对系统服务和无线 Agent 签名、响应及 AP 读取能力。
- 自动测试：130 项，1 项外部只读测试跳过，0 失败。覆盖候选门槛、准确 AP 复测、加密与防篡改、外部操作保护、私密恢复材料不进入公开响应、特权客户端和上下文边界，以及既有认证／恢复功能。

## 实机结果与验收边界

当前连接的 AP 约 -35 dBm，为同网络扫描中的最佳候选。实际调用公开 CoreWLAN 关联与断开接口后，系统未采用测试选择的较弱 AP，最终仍确认原 AP 关联。因此没有把 API 返回成功写成 BSSID 切换成功，也没有声称“弱 AP → 更优 AP”已通过实机验收。

该正向验收需要当前连接确实弱于另一个可用 AP 的场景。届时点击“一键自动优化”，以实际 AP、请求结果及恢复记录核对。软件不承诺持续锁定 BSSID，也不保证高于其他住客的共享带宽。

企业认证、需要交互的 WiFi 凭据、其他 macOS 版本及其他硬件尚未完成实机覆盖。既有系统级服务的跨网络重连限制不等于新的同网络 AP 服务不可用，两者在能力列表中分别显示。
