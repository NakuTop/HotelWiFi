# 隔离网络上的真实写入验收

默认 `swift test` / `Scripts/test.sh` 不注册服务、不修改宿主 DNS/代理、不关联、不切 WiFi。进程崩溃测试的后端只写 `/private/tmp/HotelWiFiFault-*` 中的模拟字段。

真实写入流程必须在独立测试 Mac 或已明确划定的测试 WiFi 上完成。此交付没有执行以下步骤，也没有更改开发机器的网络配置。

## 前提与范围

1. 使用默认项目专用本机证书或自己的 Developer ID Application 构建，安装到固定 Applications 目录；验证三个二进制的证书固定要求或 Team ID，以及固定标识。
2. 使用无工作会话、无 VPN、无企业分流域、无受管 profiles 的测试网络。事先用系统设置保存 DNS / 自动发现原始状态；记录配置字段是否原本存在。
3. 在应用中保存只针对 DNS 或普通自动发现的一项实验授权，批准 SMAppService；检查 helper、定位、服务读取及网络事件能力。任一能力不满足时停止写入测试并保留状态，不删门禁。
4. 用测试路由器制造可重复的 DNS 解析故障，保持公共候选 DNS 与两个 HTTPS 服务商可达。正常 DNS 不应因为略微更快被修改。代理测试单独进行，不与 DNS 同时进行。

启用真实写入的显式开关是 **项目本机证书或 Developer ID 签名 + 注册/批准辅助服务 + GUI 保存单项写入策略** 三者同时成立。没有隐藏的环境变量可跳过恢复或身份校验。测试套件即使开启只读外网测试也不会启用它们。

## 测试记录

每例保存时间、macOS 版本、构建摘要、门禁状态、事务 ID、实际字段前后值的脱敏比对、最终应用复测及恢复结果。禁止保存 WiFi 密码或门户凭据。

| 实机验证 | 合格条件 |
|---|---|
| 正常网络优化 | 零写入、零重连，最终两个服务商完整成功 |
| DNS 异常候选 | 先独立请求证据，再 A/B/A/B，只有两次重复改善且最终验证成功才提交 |
| 无收益/退化 | 原字段恢复；原本自动 DNS 仍为自动，不写回 DHCP 运行地址 |
| 主应用 SIGKILL | 不启动主应用也能由 guardian 撤销临时字段；报告分开说明配置与连通性 |
| helper 重启/系统重启 | 接受新写入前处理遗留记录，恢复幂等 |
| 用户中途改 DNS | 保留用户改值，记录冲突，不覆盖 |
| 用户关闭 WiFi | 不重新打开；只清理本程序仍持有的字段 |
| 酒店→公司/同名网络 | 清理临时字段，不重连旧网、不恢复旧 IP、不自动重放历史策略 |
| 睡眠/唤醒 | 睡眠不因心跳缺失反复恢复；唤醒清理后需重测 |
| 权限撤销/日志不可写 | 阻止新修改，已有事务进入明确恢复/等待状态 |
| 正常退出/卸载 | 先处理自身字段，确认后注销服务；不删用户网络设置 |

这些实机结果需要记录在 `Docs/VALIDATION.md`；模拟单元测试或真实只读测试不能代替本表。

## 1.1 关联和地址恢复验收

独立测试路由器/网络上逐项开启，不能在工作 WiFi 上直接运行整个测试矩阵。授权短暂重连、低流量中断及具体动作；其他已保存网络必须由本次扫描选择和确认可能费用。建立专门故障后，再执行一键优化。

| 动作 | 需要实测的证据 |
|---|---|
| DHCP | 原 ConfigMethod 为 DHCP；IPv4/IPv6/路由异常与应用失败重复成立；系统刷新请求返回后等待实际地址事件，不强占旧租约 |
| 重新关联 | 记录请求前后实际 SSID/BSSID/信道，验证一次请求、没有 WiFi 电源循环；需要新密码时拒绝 |
| 所选保存网络 | 扫描、连接级令牌、网络身份、90 秒期限、可能费用确认均通过；新连接两窗口及最终验证通过后停止 |
| AP 优选 | CoreWLAN 返回成功但 BSSID 不同或不可读时不显示指定 AP 成功；后续漫游不反复重连 |
| 中断与恢复 | APPLY 后杀主应用、重启 helper；在仍属于本次候选时最多恢复原网络一次，记录实际结果 |
| 用户介入 | 用户关 WiFi、切公司网、修改 DNS/地址、开启 VPN 后，旧任务不继续关联 |
| 完成与退出 | 最终验证后关联交还 macOS，退出不为恢复旧 AP 而再断网；DNS/代理临时字段仍清理 |
| 传输保护 | 持续传输阻止关联；低流量但未单独授权未知会话中断时也阻止 |

模拟测试不调用上述真实操作。当前正常连接不满足故障门禁时，正确验收结果就是零写入，不能为了“测到重连”撤掉门禁。
