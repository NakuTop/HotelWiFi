# 1.4.1（build 18）验证范围

日期：2026-10-23

本次按用户要求完成不需要移动 Mac 的验证。现场弱 AP 到更优 AP 的正向切换、真实未认证酒店 WiFi 与各 VPN 客户端的组合仍需相应环境，不能用模拟结果代替。

## 回归证据

新增测试直接导入生产 Radio Agent，在实际控制队列和工作队列上运行，替换的只有无线环境、特权断开接口及时间。不会注册系统服务或操作本机无线连接。

初次回归复现了扫描期间停止后仍断开、扫描期间外部切网被覆盖的问题。修复后在最终写入边界核对事务、停止状态、有效期、心跳、流量和准确连接快照。恢复时也进行相同的连接保护。

19 项服务流程覆盖：

- 两次稳定扫描、准备、加密落盘、实际目标确认、两轮正常系统路径请求、提交的完整模拟流程。
- API 返回成功但没有实际切换时不能提交；切换后抛错时恢复原 AP。
- 扫描期间停止、会话过期、外部切网，以及恢复扫描期间再次切网时不再写入。
- 持有事务的客户端失联、心跳超过 45 秒、180 秒绝对有效期及服务重新启动后的恢复。
- 身份未知时保持恢复待确认，不冒充成功；恢复请求不能被迟到的提交覆盖。
- 手动关闭 WiFi、修改配置时保留外部操作；未确认的恢复请求最多执行一次并报告冲突。
- 错误客户端、nonce、事务、缺少两轮有效复测和仅供往返验收的模式均不能提交。

应用流程同步废弃开始恢复前的旧复测窗口，并在 AP 恢复未确认时停止后续优化尝试。

## 已安装服务与包的核对方法

`hotelwifi radio-check --json` 检查签名服务响应、身份可读、未授权准备请求拒绝、错误事务的执行／提交拒绝、普通 CLI 的特权断开请求拒绝，以及前后恢复事务不变。不发送可执行的 AP 关联请求。

在没有活动事务时重启用户无线服务，重新检查 XPC 与身份权限。随后运行一次一键自动优化，核对无更优 AP 时保留当前连接。安装与包检查分别核对签名、四个可执行文件的通用架构及 SHA-256，并从 DMG 和 ZIP 重新读回。

实际运行结果记录在本次交付的升级验证记录中。模拟流程通过不代表已通过真实弱 AP 到更优 AP 的验收。
