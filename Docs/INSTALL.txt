HotelWiFi 1.4.1 — 安装与使用
修复设置中开启“一键自动切换到更优的同网络 AP”；本次自动升级已为你开启。
无线身份由用户会话 Radio Agent 使用应用获准的定位权限读取。
同网络出现经两次扫描确认的更优 AP、且传输状态允许时会执行切换；
两轮正常网络请求和最终验证通过后保留，否则请求恢复原 AP。
系统未采用目标 AP、没有更优候选或传输繁忙时，会显示相应结果。
适用于 macOS 14 及以上；同一安装包包含 Apple Silicon 和 Intel 版本。

首次安装
1. 把 HotelWiFi.app 拖进旁边的 Applications（应用程序）文件夹。
2. 从“应用程序”打开 HotelWiFi，不要直接在磁盘映像中启用后台服务。
3. 当前版本使用项目专用证书签名，尚无 Apple Developer ID 与公证。
   若 macOS 提示无法验证开发者或尚未经 Apple 检查，在尝试打开后进入：
   系统设置 → 隐私与安全性 → 仍要打开，并确认 HotelWiFi。
   只批准这个应用，不需要关闭系统安全功能或安装证书。
4. 点击“允许读取名称”并同意系统定位授权，仅用于 WiFi 名称/接入点读取。
5. 需要系统修复功能时，在应用中完成“修复后台服务”和管理员批准。
   本机检查和应用请求测试可以独立使用；具体修复操作以运行时能力为准。

使用
连接酒店 WiFi 后点击“一键自动优化”。识别到认证时自动打开内置登录窗口。
连接变化后也会自动检查认证；可在修复设置中关闭。
登录窗口不继承系统 HTTP/SOCKS/PAC 代理，认证后自动复测正常网络路径。
房号、验证码及条款需本人完成。若强制 VPN 仍阻止窗口连接，按窗口提示
在 VPN 中临时允许本地网络，再重新加载。仅打开登录页不算修复成功。
未解决时点击“复制测试报告”，可粘贴给 ChatGPT 或提交问题。
需要中止时点击“停止并恢复”。退出时会清理仍持有的临时字段。
本机链路/地址/配置检查可离线运行；酒店网页登录、密码和外部网络故障
仍需要相应操作。当前版本不提供 AP 锁定，旧系统级后台仍不能获取定位权限；同网络 AP 优化使用新的用户会话服务。
其他已保存网络的切换仍遵循原有授权和限制。

更新
先在旧版点击“停止并恢复”，进入“修复设置 → 更多选项”，执行
“卸载前恢复并注销服务”。确认完成后退出旧版，再拖入新版替换。
重新打开后按需启用后台服务。保留应用自己的恢复记录与授权偏好。
不要直接覆盖仍在运行或恢复状态不明的后台服务。

卸载
同样先停止、恢复并注销服务，确认完成后退出，把应用移到废纸篓。
这不会删除用户原有网络配置、密码或其他软件的设置。

无需安装 Python、Homebrew、Xcode 或运行终端命令。
